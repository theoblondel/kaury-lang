# Changelog

## Unreleased

- **A site in several languages, written once.** Asked for by the assistants that were tested (a site in two languages meant writing every page twice). `lang "fr", "en"` in `site` gives the languages, the one the file is written in first; a block `translate "en"` holds each text of the file and its translation, two texts side by side on a line (`"Réserver une table" "Book a table"`). Every page is then built in each language — `/carte` and `/en/carte` — with its `<html lang>`, the `hreflang` links of its versions (written like its canonical address), both in the sitemap, dates and prices in its language, the × of a dialog named in it. A text is found by what it says, wherever it is written: a title, a button, the hint of a field, the description of an image, a `seo` line, a word of `links`, a text inside a list of the file (made once per language, when a page reads it). Between braces, a translation uses the values of its text (`"Merci {name} !" "Thank you {name}!"`), and one that reads a value its text does not have is an error. An address of the site written in the file leads to the same page in the language of the page (a file such as `/photo.jpg` stays where it is), and the new element **`languages`** is the switch: FR · EN, the same page in each language, the current one marked. Pages stay static when they were: a translated text costs no JavaScript. The compiler warns for a text shown without its translation (with the line to add) and for a translation that matches no text (with the text meant, when one is close). French: `traduis`, `langues`. Content files (Markdown, YAML) are not translated by it.
- **The language of a page is the one of its dates and prices**: a page with its own `lang` formatted them in the language of the site.
- **A window over the page: `dialog`.** Asked for by the assistants that were tested (they had no way to open a booking form or a detail over the page). `dialog booking, "Book a table"` with its content indented below is shown while the true/false state `booking` is true: `button "Book" -> open booking` opens it, `close booking` (after a form is sent, say) closes it. It is the browser's own `<dialog>`: the focus stays inside, the page behind is out of reach and does not scroll, and Escape, its × button (named “Close” in the language of the site) and a click beside it close it and put the state back to false. Its content is in the HTML of the page from the start, and its titles are never the `<h1>`. French: `fenetre`, `modale`. What is written by habit — `modal`, `popup`, `lightbox` — is answered with the Kaury form.
- **A site whose address is https sends `http://` there**: the `.htaccess` written for Apache hosts redirects (301) when `url` starts with `https://` — dev.kaury.studio answered on `http://` too. Without an https address nothing changes, so a test on a local Apache keeps working.

## 1.0.0 — 12 October 2026

Nothing passes in silence: a mistake is caught with its line and its fix, or the build stops.

- **Habits from other languages get the Kaury form.** What is written from HTML, CSS, JavaScript, React or Python is answered with the Kaury way to say it: `font-size 20` → `in Kaury: size 20`, `h1 "Title"` → `in Kaury: title "…"`, `&&` → `"&&" is written "and"`, and the same for `div`, `onClick`, `className`, `=>`, `===`, `var`, `elif`, `True`, a `:` after an option, `function add(a, b)`, `{ }` blocks, `;`, `#` comments, tags.
- **Every mistake of writing in one go.** The compiler no longer stops at the first one: a refused line is left out with its block, the reading goes on, and `kaury check` lists them all (the first of each line). A page written with the braces, the `;` and the tags of JavaScript and HTML gets all its answers in one round instead of one per round.
- **A forgotten comma is named**: `title "Hello" size 80` → `a comma is missing before "size"`.
- **Values are checked.** An option that takes a number refuses a word or a text without number (`size large`, `radius "big"`); an option that takes a color refuses what is not one (`color FF0000` → `color #FF0000`); every CSS color name is accepted (`tomato`); an option without value refuses one (`bold true`); a unit apart from its number is said (`size 20 px` → `size 20px`).
- **Functions**: a function of the file called with too few or too many values says which ones it takes; a function written as the content of an element without being called (`text add 1, 2`) is an error instead of showing its code in the page.
- **Empty values**: reading a property of an empty value gives nothing (`user.name` while `user` is `none`) instead of stopping the page; calling something on it stays an error, said clearly.
- **A page that fails while it is built stops the build**, with its `.kaury` line, its text and the reason — before, the build went on and published the page with a hole in it.
- **`kaury check` renders every page** (without writing the site, without downloading anything): what only fails when a page is displayed is in its list, and in `--json`, which now also gives the number of pages.
- **Files and links that lead nowhere get a warning**, with their line, in `kaury build` and `kaury check`: a file that is not in `public/` (`image "fotos/can.jpg"` → `did you mean "photos/can.jpg"?`), an address of the site that is no page (`link "About" "/about"`, `button …, to "/buy"`, `go "/gone"`), a `#name` that names nothing in the page.
- **One menu for the whole site**: `links About` on a page that has no section `about` leads to the page that has it (`/#about`) instead of nowhere. The blog template had that dead link on every post.
- **Robustness**: a setting of the site written without its value (`lang` alone) crashed the compiler, and a property read on a number wrote invalid JavaScript (`0.float`); both are fixed, storing into a number or a text is an error, and the damage test now runs 3000 files, half of them with Windows line endings.
- **A state kept in the browser no longer breaks the page.** With `persist` (a cart), the HTML made at build time and what the visitor had saved differ: inside an `if` or a `for` that difference was reported as an error and the page was left half-built. The page is now rebuilt whole, in silence.
- **`pin` and `sticky` keep their place when `front` is written with them** (a cart drawer pinned to the corner and in front of the page): `front` put the element back in the flow.
- French: `zone-texte`, `liste-deroulante`, `case-a-cocher`, `pied-de-page`, `en-tete` are understood; a misspelled element is answered with its French name; a line whose first word is unknown gets one answer instead of one per word.
- **A button written directly in a section keeps its own width.** The usual hero — a title, a text, a button — stretched the button across the whole page; it now sits at the edge of the content, in the middle under `center`. The same for a link and an icon.
- **A site built to be published carries no debugging files**: `kaury build` wrote a `.map` next to every script (more than half the weight of the site of the language, which no visitor reads). They are written while developing only (`kaury dev`), where an error in the browser shows the line of the `.kaury` file.
- **A third group of assistants** (8, after the table and the chart, on the requests the others had turned down): 8 files without an error or a warning at the first try, and the page of figures written with `Stats`, `Chart` and `Table` in about sixty lines. From what they asked: `type time` on a field (a table booked for 19:30), `scale` on `Chart` (two years on the same scale), and the specification now says what is not pixels (`line-height`, `opacity`, `weight`), that `header` and `section header` are the same bar, that two fields can fill one state, where an object of a scene stands, and what Kaury is not for (payments, one widget for an existing site, a large documentation site).
- **Figures: `Table` and `Chart`**, two ready-made blocks asked for by the assistants that were tested (they drew tables with grids and bars with boxes, and preferred HTML for a page of figures). `Table rows, columns, "Heading"` is a real `<table>` made from a list as it is: each column has a `label` and a `field`, a `format` (`"price"`, `"date"`, `"number"`) and `align: "right"`; a click on a column sorts by it, a second click the other way, and `aria-sort` says so. `Chart items, "Heading", " CHF"` draws bars from `{ label, value }`, the tallest one filling the height, and says its figures to a screen reader. Both follow the list they are given: a `let` made from a state switches a year in one line.
- **`format-number 23490`** → `23,490`, in the language of the site (`format-number(3.14159, 2)` → `3.14`): `price` was the only way to get a separator.
- **A choice written on one line is a value at the start of a line too**: `if kind == "price" then price(v) else v` as the last line of a function was refused (“I did not expect "else" here”).
- **A box given the tag of a table is laid out as one** (`box tag "table"`, `tag "tr"`, `tag "td"`): its cells were stacked.
- **Tested with fresh assistants** (12 October 2026): twenty of them, from the smallest model to the largest, each wrote a different site from `docs/kaury-ai.md` alone, without the compiler. 11 of the 20 compiled at the first try; with what follows, 18 of the same 20 files do, 19 after one round of the checker's answers, and a second group of 8, on the hardest requests and with the corrected specification, gave 8 files without an error or a warning.
- **What is written by reflex is understood**: a comma right after the element (`row, gap 16`); an option on a line of its own under its element (`padding 80 48`, `hover lift 4`, `attr "role" "progressbar"`), like the `mobile …` lines; the look of the site line by line in `site` (`radius 20`); one of your styles alone under its element (`wide`), which was accepted as `style wide` and did nothing; a section, a nav or a header named like one of your styles takes it; on a box, a style wins over a value of the same name (`for step in … / row step`).
- **French**: `rangee`, `rayon`, `largeur-max`, `graisse`, `leve`, `aucun`, `pointeur`, `ombre douce`, `ligne` (the color) are understood, and the specification lists every French word (section 8, kept exact by a test).
- **New**: a slider (`field years, type range, min 5, max 40, step 1`; a `number` or a `range` field holds a number); `required` on `select` and `checkbox`; `to-date "2027-06-12 14:00"` (one date minus another gives the milliseconds between them: a countdown showed 0, nothing made a date).
- **A waiting picture for 3D**: a built-in shape shows its silhouette, drawn by the page in its color, at its size and at its place, from the first paint until the 3D is ready, and where a device cannot do 3D. Before, there was nothing there until the visitor's first gesture.
- **A page that runs code carries its own rules**: it had the stylesheet of the whole site, because what it shows can change. It now leaves out what it can never show: the classes made for the other pages, and, in a site of one file, the named styles and animations that neither it nor the components it calls use (a page without code already lost the rules of the elements it does not have).
- **Content files are checked**: a field read on an entry (`post.titel`, `about.nmae`) that no file has gets a warning with the one meant; before, it showed nothing, in silence.
- **Answers of the compiler, read by those who got them**: a word that is no option in a style is answered with the options of a style, in the language of the file; a state that does not exist with its condition (`checked (…)`) is answered with the two ways there are; a word with lines under it that is no element says so (it said “this indented block belongs to nothing”); a style or screen line lost in a loop or a condition says where it goes (the build failed on another line); a heading that skips a level inside a component is shown where it is written; a text over a background written under its box is no longer compared to the page.
- **Fixed**: the height written on a scene is its height (`scene height 300` stayed 540 px tall); a section named with an accent (`réalisations`) is found by `links`, by `to "#réalisations"` and by a link, and its id has no accent.
- **One main heading per page.** `title` is written for every part of a page, and each one was an `<h1>`: the home page of the language had two. The first title sure to be there is now the `<h1>`, the next ones are `<h2>` by themselves and keep the size of a title; a title that shows in one case only (a menu that opens) takes no place, the two sides of an `if` are one place, and a block or a component that brings a title (`Hero`) counts. `level` on the line still decides. A `markdown` text that starts with its own `# Title` under the title of the page goes one level down, whole.
- **`level` works on a subtitle**: `subtitle "…", level 3` was accepted and ignored (an `<h2>` every time); it now makes the `<h3>`.
- **What a field fills is known in the whole page**: the thank-you message written above its form (`text "Thank you {name}!"`) no longer says that `name` does not exist.
- **Fields**: the first word of a field is the state it fills, even when an option has that name. `select size "S", "M", "L"`, the example of the docs, was read as the text size and its choice went nowhere.
- **Suggestions** never propose a JavaScript global any more (`buton` → `button`, not `btoa`); `3 colums` proposes `columns`.
- The ready-made blocks describe their images (the name of the person for `Team` and `Testimonials`), so they give no warning the author cannot fix.
- An indentation that is not 2 spaces gets a warning.
- The specification for AI assistants (`docs/kaury-ai.md`) is up to date (0.4), every one of its examples is compiled by the tests, and it has a new section: the Kaury form of what one knows from HTML, CSS and JavaScript.

Measured with Lighthouse on sites written from the specification alone, then found by designing three real ones (`examples/lina`, `examples/forge`, `examples/nuit`):

- **A page without `seo` gets its description by itself**: its first paragraph, cut at a sentence. A page written with no thought for search engines scores 100 in SEO.
- **Tabs are announced as tabs**: buttons with `selected` in the same row get `role="tablist"`, `role="tab"` and `aria-selected`; alone, `aria-pressed`.
- **Warnings for what a visitor cannot use**: a heading level that is skipped (`level 2` then `level 4`), a button whose text cannot be read on its color, an accent color on which no text is readable (with a shade nearby that is).
- **A page adopts its HTML with what the server had**, then takes the real screen and the saved states: `screen.mobile` and `persist` no longer make every phone rebuild the page.
- **`shade`** darkens a background picture so the text in front stays readable: `section hero, background "hall.jpg", shade 0.6`, or toward one side only, `shade 0.9 bottom`. From 0.4 the text turns light by itself.
- **`grayscale`** shows a picture in black and white (photos from different sources brought to one look); `hover grayscale 0` gives the colors back. Several filters on one line add up (`grayscale, blur 4`).
- **`middle`** puts a block in the middle of its row or of its grid line (a text next to a tall photo). **`upright`** takes the italic away (an emphasis shown by its color alone: `style emphasis`, then `upright, color accent`).
- **A size written for one screen is that size**: `mobile size 46` gave 22 pixels, the fluid shrinking of big texts being applied a second time. And a size a little above 36 no longer ends smaller on a phone than the text around it (`size 38` became 18 pixels; it now stays at 30 or more).
- **A named style or a size written on a title wins**: the rule of `level 2` and `level 3` headings outranked them.
- **A button with its own background keeps no glow of the accent color**: an outlined button on a green site had a green halo under an empty frame.
- **In a `no-wrap` row the texts stay on one line too**: in a ticker, "Open gym" was cut in two.
- **`direction column` lets the children take the whole width** (a footer in a column: its row was shrunk and centered, and `margin 0 0 0 auto` pushed nothing). `center` on the same line keeps them centered.
- **A text is read on the background of what contains it.** A color written for a text (on its line or in its style) is compared with the background of the box it sits in, through rows, `for` and `if`: a label fine on the page and too pale inside a tinted card gets a warning, with a shade next to it that can be read there. A text made faint with `opacity` is read as it is seen. A big pale text that is only decoration says so with `attr "aria-hidden" "true"`. Nothing is said when the background is a picture, a gradient or a style under a condition.
- **Pages led by photographs are fast.** Measured on the three examples (phone): 86, 85 and 66 in performance before, 95, 98 and 96 after; 100 on a desktop, and 100 in accessibility, best practices and SEO.
  - A picture written as a background (`background "hall.jpg"`) is served in the light versions made for images, a smaller one on phones, and the one that opens a page is announced to the browser instead of being found after the stylesheet.
  - Only the first image of a page loads at once; the next ones wait for their turn instead of taking its bandwidth.
  - An image hidden on a screen (`mobile hidden`) is no longer downloaded first where nobody sees it.
  - An image with its width written (`width 210`) is fetched at that size.
  - Images are also made 800 and 1280 pixels wide: what a phone and a tablet really ask for.
- **The ready-made blocks are redrawn.** Their look is the look of most sites an assistant writes, and it was the look of a template: a centered hero, three equal cards twice, a grey that could not be read on a colored plan. Same values, same names, a new drawing: nothing centered by default and the headings on the edge of the content; `Hero` puts its picture beside the text; `Features` is a list in two columns; `Testimonials` opens with one large quote; the featured plan of `Pricing` is filled with the accent color; `Faq` and `Contact` have their heading beside them; `Cta` has its sentence on one side and its button on the other. What is soft is soft by opacity, so every block can be read with a dark or a light accent, on a light or a dark site (checked by the tests on four palettes). The landing template no longer uses emoji as icons nor invented figures.
- **A site can live in a folder of another site**: `kaury build --base /project/` (GitHub Pages, a demonstration inside a site). Every address of the site starts with the folder, in the HTML that is served and in what the page writes later: pictures and their light versions, pages, scripts, fonts, 3D models, data.
- **The site of the language is redrawn**, and its address is `dev.kaury.studio`: a dark first screen with one object in 3D, real sites running in the page (the three designed examples and Crush, built whole under `/showcase/`), a showcase page with the code of each one, the scores as they were measured.
- **The text no longer moves when the web font arrives.** The width each font writes at is read from its file, and the device font shown meanwhile is scaled to it: the lines break at the same place before and after. A row of buttons that took one line less made a page jump (0.15 of layout shift, now 0).
- **The font file loaded first for the titles is the one they use**: a site with thin titles loaded the bold file first, and its headline came late.
- **Two more things no longer pass in silence**: a style written on a box that it cannot style (named after another element, as `column card` with `style card`, or misspelled: `column tintd`), and a function alone on its line that nothing keeps nor calls (`onver -> …` for `on hover -> …`), which compiled to JavaScript no browser could read. Found by damaging the designed examples 21,000 times: no crash is left.
- **An object placed to the side of a scene stays in the picture on a phone**: on a narrow screen it comes back toward the middle and peeks at the edge, instead of being out of view.
- **A site shown in a frame of the same site** (a preview in a gallery) starts its 3D on a gesture made on the page around it, not only inside the frame.
- Two more designed examples: `examples/terre` (a shop: one page per piece made from a list, a basket kept in the browser) and `examples/relay` (a product page with no photograph, its panel and its charts drawn in Kaury and alive).
- **Three designed examples** with real photographs: a restaurant (`examples/lina`), a gym (`examples/forge`), a perfume launch with one object in three dimensions (`examples/nuit`). Each one passes `kaury check` with no warning.

Earlier fixes of this version: `max-width` and `width` no longer center (`center` does) and apply to what is directly in a section; several named styles on one line; a named style under a condition (`card-wide (i == 0)`); `field` and `label` parts in a style; `base64` and `encode-url`; computed values for `min-height`, `max-width`, `line-height`, `weight`, `tracking`; warnings for a style never used, a computed value that is ignored, a text hard to read on its background, an image without description, a 3D object without `alt` nor `fallback`.

## 0.4.0

- **Ready-made blocks**: `Hero`, `Features`, `Steps`, `Stats`, `Pricing`, `Testimonials`, `Team`, `Logos`, `Gallery`, `Faq`, `Cta`, `Contact`, `Footer`. Written in Kaury, added by the compiler when a page uses them, in the site's colors and fonts. A component of the same name in the site replaces one.
- **Forms that send e-mails**: `form mail "hello@you.com", subject "…" -> …`. `kaury dev` shows the e-mail in the terminal; with `KAURY_MAIL_KEY` (a resend.com key) it is really sent. `kaury build` writes the endpoint for Netlify, Vercel, Cloudflare Pages and PHP hosts filled by FTP (`dist/api/kaury-mail.php`, key in `kaury-mail-key.txt` next to the site's folder). The address never appears in the page, the endpoint only writes to the site's addresses, and robots are ignored.
- **Templates**: `kaury new my-site --template landing | blog | portfolio` (the default `starter` still teaches the language).
- **Theme colors and fonts**: `accent`, `on-accent`, `ink`, `muted`, `line`, `font "titles"`, `font "text"`.
- A component called with too few or too many values says which ones it takes.
- `links Features` links to the section even when a component has that name.
- A named style can make a column, box, grid or row in a section narrower (`max-width 640`).
- An empty `id` is left out of the page.
